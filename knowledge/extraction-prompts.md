# Gemini Notebook 知識抽出プロンプト集（Step 1）

## 使い方

1. Gemini アプリでノートブック「lp marketing harness」を開き、**新しいチャット**で実行する（前の会話の影響を避けるため）。
2. 最初に「共通指示」を送り、続けて P1〜P9 を**1つずつ**送る。
3. 回答はそのまま `knowledge/raw/P1.md` のようにファイルにするか、チャットで責任者に貼り付ける。
4. 回答が途中で切れた場合は「続けて」と送り、続きも一緒に貼る。

---

## 共通指示（最初に1回だけ送る）

```
これからLP制作を自動化するシステムのために、このノートブックのソースから知識を抽出してもらいます。以下のルールを必ず守ってください。

1. ソースに書かれている内容だけを使うこと。あなた自身の一般知識で補わないこと。補う必要がある場合は、その項目に「出典なし」と明記すること。
2. 各項目に出典（動画タイトルと、分かればおおよそのタイムスタンプ）を付けること。出典は「source: 1」のような番号ではなく、動画タイトルを省略せずに書くこと。
3. 具体的な数値・事例・言い回しがソースにあれば、要約せずできるだけそのまま残すこと。
4. 出力は指定するYAML形式のみで、前置きや感想は不要です。
5. ソース間で主張が食い違う場合は、両方を別項目として出し、conflicts_with に相手の項目IDを書くこと。

出力形式:
- id: <カテゴリ略号>-<3桁連番>
  title: <原則を一行で>
  statement: <具体的に何をすべきか／すべきでないか>
  rationale: <なぜそうするのか（ソース中の理由）>
  evidence: <ソース中の具体的な数値・事例・発言。なければ空>
  applies_when: <適用条件。商材・業種・価格帯など。限定がなければ「常に」>
  anti_patterns: [<やってはいけない例>]
  sources:
    - video: <動画タイトル>
      timestamp: <mm:ss または 不明>
  conflicts_with: [<矛盾する項目ID>]

了解したら「OK」とだけ返してください。
```

## 途中から使う場合の補足（P4 以降を既存チャットで続けるとき）

P1〜P3 の回答では出典が「source: 1」のような番号になり、どの動画か特定できませんでした。
P4 以降を同じチャットで続ける場合は、各プロンプトの末尾に次の1行を付け足してください。

```
sources の video には「source: 数字」ではなく、動画タイトルを省略せずに書いてください。
```

## P1: 全体像・考え方（略号 CORE）

```
カテゴリ CORE として、「売れるLP」についてのソース全体に通底する考え方・哲学を抽出してください。
例: LPの役割、ホームページとの違い、制作会社に任せてはいけない理由、誰がLPを作るべきか、LPで最も重要な要素は何か、など。
漏れなく、最低でも10項目以上出してください。
```

## P2: リサーチ・ターゲット・訴求軸（略号 STR）

```
カテゴリ STR として、LPを作る前の「リサーチ」「ターゲット設定」「訴求軸・コンセプト・USPの決め方」に関する原則を抽出してください。
顧客の悩みの掴み方、競合の調べ方、訴求の切り口を何パターン用意するか、についての言及も含めてください。
```

## P3: ファーストビュー（略号 FV）

```
カテゴリ FV として、ファーストビュー（LPの最初の画面）に関する原則をすべて抽出してください。
キャッチコピー、画像、権威付け、CTAの有無、離脱率との関係、FVだけ差し替えるテスト、などへの言及を含めてください。
```

## P4: LP構成・情報の順番（略号 STRUC）

```
カテゴリ STRUC として、LP全体の構成（セクションの種類と順番）に関する原則を抽出してください。
可能であれば、ソースで推奨されている構成を「セクション名 → そのセクションの役割」の順番付きリストとして、最後に別項目 STRUC-TEMPLATE で出してください。
LPの長さ（縦長か短いか）への言及も含めてください。
```

## P5: コピーライティング（略号 COPY）

```
カテゴリ COPY として、LPの文章（見出し・本文・言葉選び）に関する原則を抽出してください。
ソース中に出てくる「良いコピーの実例」「悪いコピーの実例」があれば evidence にそのまま引用してください。
```

## P6: デザイン・画像・スマホ対応（略号 DES）

```
カテゴリ DES として、LPのデザイン・画像・動画・フォント・色・スマホ表示・表示速度に関する原則を抽出してください。
「デザインにこだわりすぎるべきか」についての言及も含めてください。
```

## P7: オファー・価格・CTA・フォーム（略号 OFR）

```
カテゴリ OFR として、オファー設計（価格・特典・初回割引・保証）、CTA（ボタンの文言・位置・回数）、申込フォーム（入力項目・離脱対策）に関する原則を抽出してください。
```

## P8: 運用・ABテスト・数値（略号 OPS）

```
カテゴリ OPS として、LP公開後の運用改善に関する原則を抽出してください。
ABテストの進め方（何パターン作るか、何から変えるか、判定基準、期間）、見るべき数値（CVR、CPA、LTV、離脱率など）とその目安、改善の優先順位、広告との関係、成功事例の数値（例: 4ヶ月で売上がどうなったか）を含めてください。
```

## P9: 失敗パターン・業種別の注意・未解決点（略号 RISK）

```
カテゴリ RISK として、以下を抽出してください。
1. ソースで指摘されている典型的な失敗パターン（業者選び、ありがちなLPのダメな点など）
2. 業種別（特に化粧品・健康食品）の注意点
3. 法律（薬機法・景品表示法など）に関する言及
最後に、別項目として「ソースだけでは判断できない・情報が足りない論点」を列挙してください（id は RISK-GAP-xxx）。
```

## 補足: 既存チャットの回答

ノートブックに既にあるチャット「売れるLP運用の成功原則」の回答も参考資料として有用です。
可能であれば全文を `knowledge/raw/existing-chat.md` として共有してください。

## V1: 動画別の索引（出典特定用）

Gemini の「source: 番号」は回答ごとに変わるため、動画単位で主張と発言を出してもらい、責任者が原則と照合して出典を確定する。
新しいチャットで、共通指示を送らずにこれだけを送る。途中で切れたら「続けて」と送る。

```
このノートブックのソース動画を、1本ずつ順番にすべて取り上げてください。
動画ごとに次の形式で出力してください。前置きは不要です。

- title: <動画タイトルを省略せず全文>
  speaker: <主に話している人。分からなければ「不明」>
  format: <対談 / 講義 / LP添削 / コンサル実演 など>
  theme: <動画の主なテーマを1行>
  claims:
    - claim: <その動画で語られている主張を1行>
      quote: <その主張を裏付ける特徴的な発言をそのまま引用>
      timestamp: <mm:ss、分からなければ「不明」>

ルール:
- ソースに書かれていることだけを使い、一般知識で補わないこと。
- 1本あたり主張は5〜15個。LP・広告・価格・運用・法律に関する主張を優先すること。
- 具体的な数値（CVR、売上、期間、価格など）は必ず残すこと。
- 最後に、ソース動画の総数と、全タイトルの一覧を出すこと。
```
