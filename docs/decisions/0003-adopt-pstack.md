# ADR-0003: pstack を進め方の基本として、スキルとルールでリポジトリに取り込む

- ステータス: **決定**（監査人の承認 2026-09-26）
- 日付: 2026-09-26

## 背景

監査人から pstack の導入依頼があった。調査の結果、pstack は次のものと判断した。

- Cursor の Lauren Tan 氏（poteto）が作った、AI エージェント向けのスキル集（MIT）。原本は [cursor/plugins の pstack](https://github.com/cursor/plugins/tree/main/pstack)
- 目的は「もっともらしいが検証されていないコード」を減らすこと。入口の `poteto-mode` が、調査・バグ修正・機能追加などの作業に応じて手順を選ぶ。`how`（仕組みの説明）、`why`（原因調査）、`architect`（設計比較）、`interrogate`（複数モデルによるレビュー）などのスキルと、約20の原則を含む
- 同名の Linux デバッグツール（peadar/pstack）とは無関係

Claude Code 用には [michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude)（原本に忠実な移植、スター607）を選んだ。

最初はプラグインとしての導入を検討したが、パイロットでクラウドセッションでは使えないと分かった（下記）。監査人の判断は次のとおり。

> プラグインではなくスキルとかルールとして入れて。今後はそちらのルールに従うように既存ルールを書き換えて良い。承認。

## 決定

1. **pstack-claude v0.9.45（commit `c02fd49`）のスキル54とエージェント12を、`.claude/skills/` と `.claude/agents/` に取り込む**。取り込みは `scripts/vendor_pstack.py` で行い、変更はエージェント名の接頭辞 `pstack:` を外すことだけにする。出典・ライセンス・更新手順は `third_party/pstack/README.md`
2. **プラグインの起動時フックの内容（どの作業で `poteto-mode` を使うか）は、CLAUDE.md の「進め方」にルールとして書く**
3. **進め方の基本を pstack にする**。既存ルールのうち衝突するものは pstack 側に揃えた:
   - 憲章 4-3「承認なしに次のステップへ進まない」→ やり直せる作業は承認を待たずに進め、結果を示して監査人が事後に修正する（原則 never-block-on-the-human）
   - 承認を待つのは、製品の方向性（前提 P1〜P4・欠落の方針 D1・原則の承認・KPI・予算）、やり直せない操作（公開・`main` へのマージ・外部送信・削除）、法令適合の最終判断に限る。pstack の原則も「製品の方向性は人が決める」「やり直せない操作は確認する」としており、ここは両者で一致する
   - roadmap の作業規則4（ゲート規則）と footguns F-12 を同じ内容に改訂した
4. 次の既存ルールは pstack と矛盾しないので残す: パイロット規則（F-01。pstack の prove-it-works と同じ方向）、監査人への依頼は最大3件（F-14。pstack の minimize-reader-load と同じ方向）、知識データの取り扱い（ADR-0002）
5. pstack は開発の進め方の道具で、製品の技術スタック（前提 P4: Python + Claude API + 静的HTML）は変えない

## パイロットの結果（F-01）

| 確認項目 | 結果 |
|---|---|
| プラグインとして入れる | 成功。スキル54・フック1。常時約4,300トークン／セッション。`/pstack:how` を1件実行し、validate_catalog.py の検査の仕組みを正しく説明した（約2分・約0.60ドル） |
| リポジトリの `.claude/settings.json` でプラグインを宣言 | **クラウドセッションでは読み込まれない**（公式ドキュメントにも記載。`claude -p` でも自動では入らない） |
| リポジトリの SessionStart フックでプラグインを入れる | 有効になるのは次のセッションから。クラウドは毎回新しいコンテナなので使えない |
| **スキルとエージェントとして取り込む（採用）** | プラグインを入れていない新しい設定で、スキル54とエージェント12がすべて読み込まれた。名前を書き換えた `poteto-agent` をサブエージェントとして起動できた |
| 取り込みの再現性 | 2回続けて取り込んでも同じ結果。上流との差分はエージェント名の13行だけ |
| 改変の検出 | 取り込んだファイルを1文字変える、または余計なファイルを置くと、`check.sh` が失敗する |

## 代替案

| 案 | 採らない理由 |
|---|---|
| プラグイン（リポジトリで宣言） | クラウドセッションで読み込まれない |
| プラグイン（環境の Setup script で導入） | 動くが、リポジトリの外の設定に依存し、PR でレビューできない。監査人がスキル・ルールでの取り込みを選んだ |
| 必要なスキルだけ選んで取り込む | スキル同士が互いを参照している（`poteto-mode` が `babysit`・`fix-ci` などを呼ぶ）。上流も全ディレクトリを残すよう案内している |
| 別の移植版（irg1008/cstack） | 利用実績が少ない（スター4、9コミット） |
| CLAUDE.md を優先し、pstack は補助にとどめる（前回の提案） | 監査人が pstack に揃えるよう指示した |

## 影響

- **良い影響**: 原因調査・設計比較・レビュー・実行による確認の手順が揃う。承認待ちで作業が止まる時間が減る
- **監査のしかたの変化**: 監査人は「着手前に承認」から「PR で結果を見て事後に修正」に変わる。製品の方向性とやり直せない操作は、これまでどおり監査人が決める
- **コスト**: スキルの説明が常時コンテキストに入る（約4,300トークン／セッション）。`arena`・`architect`・`interrogate` は複数モデル（opus / fable / sonnet）のサブエージェントを並べるため、1回あたりの費用が大きい
- **環境の制約**: `gh` CLI が無いため、`babysit`・`fix-ci`・`get-pr-comments` などの `gh` を使う手順は GitHub MCP で読み替える（CLAUDE.md に明記）
- **更新**: 取り込んだファイルは直接編集しない。上流を更新するときは `scripts/vendor_pstack.py` の固定コミットを変えて取り込み直し、PR にする（F-30）
- **やめる方法**: `.claude/skills/` と `.claude/agents/` の pstack 由来のファイル（`third_party/pstack/manifest.sha256` に一覧）を消し、CLAUDE.md の「進め方」を戻す
